# 명세 체크리스트

명세 원본은 `docs/spec.md` 하나다. 이 스킬은 내용을 복사하지 않고 **쓰는 법**만 정한다. 항상 원본을 읽는다.

## ID 체계

| 접두사 | 영역                                                                |
| ------ | ------------------------------------------------------------------- |
| S1~S8  | 시트 편집 (선택, 입력, 이동, 서식, undo, 영속화, 그리드, 시트 목록) |
| C1~C7  | 공동 편집                                                           |
| A1~A7  | AI 편집                                                             |
| X1~X3  | 공동 편집 × AI                                                      |
| Q1~Q5  | 코드 품질                                                           |
| R1~R5  | README 산출물                                                       |
| D1~D11 | 결정 사항 (명세 해석)                                               |

항목 안의 개별 기준은 `S2-3`처럼 순번으로 가리킨다(해당 ID 아래 불릿 순서). IME처럼 이름이 분명하면 `S2-IME`도 허용한다.

## 우선순위

- **P0**: 반드시. 미충족이면 완료가 아니다.
- **P1**: 완성도. 단계 마무리 전에 처리하거나 보류 이유를 남긴다.
- **P2**: 코드 복잡도를 늘리면 하지 않는다. 제외 시 README "구현 범위"에 기록.

## 판정 값

| 값        | 기준                                                      |
| --------- | --------------------------------------------------------- |
| `met`     | 코드 위치와 동작 근거(테스트, 재현 절차)를 제시할 수 있음 |
| `partial` | 일부 기준만 충족. 빠진 기준을 명시                        |
| `unmet`   | 구현 없음, 또는 근거를 찾지 못함                          |
| `n/a`     | 아직 해당 단계가 아님                                     |

**근거를 찾지 못하면 `unmet`이다.** "아마 될 것"은 `met`이 아니다.

## 명세 변경

동작을 바꾸려면 `docs/spec.md`를 먼저 고치고 사용자 확인을 받는다. 구현이 명세와 다르게 흘러가면 구현을 명세에 맞추거나, 명세 변경을 제안한다. 조용히 벗어나지 않는다.

# 기획 명세

과제 메일의 요구사항을 검증 가능한 항목으로 쪼갠 문서입니다. 구현·테스트·리뷰는 모두 이 문서의 **ID**를 기준으로 합니다.

- 상태: **확정** (2026-09-29). 이후 변경은 이 문서를 먼저 고친 뒤 구현한다.

## 평가 기준 (과제 원문 요약)

1. **기능**: 기능 개수보다 요구사항을 꼼꼼하게, 사용자 입장에서 감각 있게 구현했는가. 적은 기능이라도 완성도 있게.
2. **코드**: 앞으로 커질 서비스의 코드를 완전히 이해하고 유지보수할 수 있는가.
   - 구현된 코드를 정확히 이해하고, 직접 정리하거나 보완할 수 있는가
   - 불필요한 중복과 복잡도를 걷어내고 코드를 정돈했는가
   - 사용한 기술을 왜 선택했는지 설명할 수 있는가
   - 코드가 읽기 쉽고 구조가 명확한가

두 번째 기준 때문에 **P2 항목은 코드 복잡도를 늘린다면 하지 않는다.** 기능을 하나 더 넣는 것보다 기존 코드를 설명 가능하게 정돈하는 쪽을 우선한다. 코드 품질 기준은 아래 Q 섹션에 둔다.

## 우선순위

| 등급   | 의미                                                                   |
| ------ | ---------------------------------------------------------------------- |
| **P0** | 과제 명세에 명시됨. 빠지면 요구사항 미충족                             |
| **P1** | 명세에는 없지만 없으면 사용자가 어색함을 바로 느낌. 완성도 평가에 직결 |
| **P2** | 시간이 남으면. README에 "제외"로 기록 가능                             |

## 용어

| 용어      | 뜻                                                                                |
| --------- | --------------------------------------------------------------------------------- |
| 참여자    | 시트를 연 브라우저 탭 하나. 탭마다 서로 다른 참여자                               |
| 활성 셀   | 키보드 입력이 들어가는 셀 (선택 범위 중 하나)                                     |
| 선택 범위 | 활성 셀을 포함한 직사각형 범위. 단일 셀도 범위의 한 형태                          |
| 편집 모드 | 셀 안에서 텍스트를 입력 중인 상태. 확정 전까지 값은 다른 참여자에게 반영되지 않음 |
| AI 제안   | AI가 만든, 아직 시트에 적용되지 않은 셀 변경 목록                                 |

## S. 시트 편집

### S1. 셀 선택 — P0

- 셀을 클릭하면 그 셀이 활성 셀이 되고 선택 범위는 그 셀 하나가 된다.
- 드래그하면 시작 셀부터 현재 셀까지 직사각형 범위가 선택된다.
- Shift+클릭은 활성 셀을 기준으로 범위를 확장한다.
- Shift+방향키는 범위를 한 칸씩 확장·축소한다. 활성 셀은 움직이지 않는다.
- 선택 범위와 활성 셀이 시각적으로 구분된다 (범위: 옅은 배경 + 테두리, 활성 셀: 굵은 테두리).
- 행·열 헤더에 선택 범위가 표시된다. — P1
- 드래그 중 포인터가 뷰포트 가장자리를 벗어나면 자동 스크롤된다. — P1
- 행·열 헤더 클릭으로 행·열 전체 선택. — P2

### S2. 값 입력·수정 — P0

- **바로 입력**: 편집 모드가 아닐 때 문자를 입력하면 편집 모드로 들어가며 기존 값을 대체한다.
- **이어서 편집**: Enter, F2, 더블클릭은 기존 값을 유지한 채 커서를 끝에 두고 편집 모드로 들어간다.
- **확정**: Enter, Tab, 다른 셀 클릭 시 값이 확정되어 문서에 반영된다.
- **취소**: Esc는 편집 중인 내용을 버리고 원래 값으로 돌아간다.
- **지우기**: 편집 모드가 아닐 때 Delete/Backspace는 선택 범위의 값을 모두 지운다. 서식은 유지한다.
- **한글 입력(IME)**: 조합 중 Enter는 조합만 끝내고 확정하지 않는다. 바로 입력을 한글로 시작해도 첫 글자가 빠지거나 분리되지 않는다. — P0 (한국어 사용자에게 가장 먼저 보이는 결함)
- 값은 문자열로 저장한다. 숫자는 오른쪽 정렬로 표시한다. — P1
- 수식(`=SUM(...)`)은 지원하지 않는다. 문자열로 저장된다. → 제외 (README 기록)

### S3. 키보드 이동 — P0

| 키                  | 편집 모드 아님         | 편집 모드                                                               |
| ------------------- | ---------------------- | ----------------------------------------------------------------------- |
| 방향키              | 한 칸 이동             | 바로 입력으로 시작했으면 확정 후 이동, 이어서 편집이면 텍스트 커서 이동 |
| Enter / Shift+Enter | 편집 모드 진입 (S2)    | 확정 후 아래 / 위로 이동                                                |
| Tab / Shift+Tab     | 오른쪽 / 왼쪽으로 이동 | 확정 후 오른쪽 / 왼쪽으로 이동                                          |
| Esc                 | 동작 없음              | 편집 취소                                                               |

- 시트 가장자리에서는 더 이동하지 않는다.
- 활성 셀이 화면 밖으로 나가면 보이도록 스크롤한다. — P0
- ⌘/Ctrl+방향키로 데이터 경계 또는 시트 끝까지 이동. — P2
- 범위가 선택된 상태에서 Enter/Tab은 범위 안에서 순환 이동. — P2

### S4. 셀 서식 — P0

- 지원 서식: **굵게, 기울임, 밑줄, 취소선** (토글) 과 **정렬(왼쪽·가운데·오른쪽), 글자 크기** (선택값) (D3)
- 정렬을 지정하지 않은 셀은 숫자면 오른쪽, 그 외 왼쪽으로 자동 정렬된다. 글자 크기 기본은 13px이고 셀 높이는 고정이다(큰 글씨는 셀 안에서 잘린다).
- 서식은 선택 범위 전체에 적용된다. 범위 안에 서식이 섞여 있으면 "모두 켜기"로 동작하고, 모두 켜져 있으면 끈다.
- 단축키: ⌘/Ctrl+B, ⌘/Ctrl+I, ⌘/Ctrl+U, ⌘/Ctrl+Shift+X
- 툴바 버튼이 현재 활성 셀의 서식 상태를 반영한다 (눌린 상태 표시).
- 편집 모드에서도 단축키로 서식을 토글할 수 있다. — P1
- 값과 서식은 독립적으로 병합된다: A가 값을 바꾸고 B가 동시에 굵게 해도 둘 다 남는다. (→ C3)

### S5. 실행 취소 / 다시 실행 — P0

- ⌘/Ctrl+Z 실행 취소, ⌘/Ctrl+Shift+Z와 Ctrl+Y 다시 실행. 툴바 버튼도 제공.
- 되돌리는 단위: 값 확정 1회, 서식 적용 1회, 범위 지우기 1회, AI 적용 1회가 각각 한 단계.
- 편집 모드 안에서의 ⌘Z는 입력 중인 텍스트의 되돌리기로 동작한다 (문서 undo가 아님).
- 되돌린 뒤 변경된 셀로 선택이 이동하거나 강조된다. — P1
- 실행 취소할 것이 없으면 버튼이 비활성화된다.
- 새로고침하면 undo 기록은 사라진다. → README 기록

### S6. 영속화 — P0

- 새로고침해도 시트 내용과 서식이 유지된다.
- 모든 탭을 닫았다가 다시 열어도 유지된다.
- 로드가 끝나기 전에는 빈 시트 대신 로딩 상태를 보여 준다 (빈 시트가 깜빡이지 않음).
- 저장소를 쓸 수 없는 환경(IndexedDB 차단 등)이면 경고를 표시하고 메모리로만 동작한다. — P1

### S7. 그리드 — P0

- 크기: 100행 × 26열(A~Z) 고정. (D1)
- 열 헤더(A, B, C…)와 행 헤더(1, 2, 3…)가 스크롤해도 고정된다.
- 긴 값은 셀 밖으로 잘려 보이고, 편집 모드에서는 전체가 보인다.
- 열 너비 조절. — P2
- 복사·붙여넣기(TSV, 다른 스프레드시트와 호환). — P2 (D5: 핵심 기능 완성 후 추가 검토)

### S8. 시트 목록 — P0 (D4)

- `/`는 시트 목록, `/sheet/[id]`는 시트 편집 화면이다.
- 목록에서 새 시트를 만들고, 기존 시트를 열 수 있다. 새 시트는 만들자마자 편집 화면으로 이동한다.
- 목록은 탭 간에 동기화된다 (다른 탭에서 만든 시트가 바로 보임).
- 시트마다 문서, 동기화 채널, 참여자가 분리된다. 다른 시트를 연 탭은 참여자 목록에 나타나지 않는다.
- 없는 id로 접속하면 "시트를 찾을 수 없음" 안내와 목록으로 돌아가는 링크를 보여 준다.
- 시트 이름 변경. — P1
- 시트 삭제. — P2

## C. 공동 편집

### C1. 합류와 초기 상태 — P0

- 새 탭에서 같은 시트를 열면 새 참여자로 합류한다.
- 합류 시점의 시트 내용이 바로 보인다. 저장 중이던 최신 변경까지 포함한다 (IndexedDB 로드 후 다른 탭에 누락분 요청).
- 합류하면 기존 탭들의 참여자 목록에 즉시 나타난다.

### C2. 실시간 반영 — P0

- 한 탭에서 값을 확정하거나 서식을 바꾸면 다른 탭에 곧바로(체감 지연 없이) 반영된다.
- 편집 모드에서 입력 중인 텍스트는 확정 전까지 다른 탭의 셀 값에 반영되지 않는다. 대신 "편집 중" 표시가 보인다 (→ C5).

### C3. 동시 편집 안정성 — P0

- 모든 탭은 변경을 받는 순서와 무관하게 **같은 최종 상태**로 수렴한다.
- 서로 다른 셀, 또는 같은 셀의 값과 서식을 동시에 바꾸면 모두 반영된다.
- 같은 셀의 값을 동시에 확정하면 한 값이 모든 탭에서 동일하게 선택된다.
- **내가 편집 모드인 셀을 다른 참여자가 먼저 확정한 경우**: 내 입력은 그대로 유지하고 "다른 참여자가 이 셀을 변경했습니다"를 표시한다. 내가 확정하면 내 값이 반영된다(LWW). Esc로 취소하면 상대 값이 보인다. (D6)
- 빠르게 연속 편집하거나 여러 탭에서 동시에 범위를 지워도 상태가 깨지지 않는다.
- 탭을 복제(Duplicate tab)해도 별개의 참여자로 동작한다 (참여자 ID를 sessionStorage에 두지 않음).

### C4. 참여자 식별과 목록 — P0

- 각 참여자는 **이름과 색**으로 구분된다. 이름은 형용사+동물 랜덤 이름을 자동 배정한다("파란 고래"). 수정 UI는 두지 않는다. (D2)
- 색은 참여자끼리 겹치지 않도록 팔레트에서 배정하고, 선택 테두리 위에서도 읽을 수 있는 대비를 갖는다.
- 현재 접속 중인 참여자 목록을 확인할 수 있다. 나 자신은 아바타의 표식과 툴팁 "(나)"로 구분된다.
- 목록에서 참여자를 클릭하면 그 참여자의 선택 위치로 이동한다. — P2

### C5. 다른 참여자의 선택·편집 표시 — P0

- 다른 참여자가 선택한 셀·범위가 그 참여자의 색 테두리로 보인다.
- 활성 셀 위에 참여자 이름 라벨이 보인다.
- 다른 참여자가 편집 모드인 셀은 "편집 중"임을 구분할 수 있다 (예: 굵은 테두리 + 라벨에 "입력 중").
- 여러 참여자가 같은 셀을 선택해도 표시가 겹쳐 읽을 수 없게 되지 않는다. — P1
- 표시는 저장되지 않으며 undo 대상이 아니다.

### C6. 탭 종료 정리 — P0

- 탭을 닫으면 그 참여자는 다른 탭의 참여자 목록과 시트 표시에서 사라진다.
- 정상 종료(닫기, 새로고침, 이동): 1초 이내에 사라진다.
- 비정상 종료(크래시, 강제 종료): 수 초 이내에 사라진다. (Web Locks 또는 heartbeat)
- 백그라운드 탭이 브라우저에 의해 절전되어도 참여자에서 잘못 제거되지 않는다. — P1

### C7. 내 변경만 되돌리기 — P0

- 실행 취소는 내 탭이 만든 변경만 되돌린다. 다른 참여자의 변경은 그대로 둔다.
- 내가 바꾼 셀을 다른 참여자가 다시 바꾼 뒤 내가 실행 취소하면: 내 변경만 되돌리고, 이미 덮어쓴 상대 값은 유지한다 (Yjs 기본 동작). (D7)
- 다른 참여자의 변경이 들어와도 내 undo 기록이 사라지지 않는다.

## A. AI 편집

### A1. 채팅으로 시트 편집 — P0

- 채팅 패널에서 지시하면 AI가 현재 시트 내용을 참고해 셀 변경을 제안한다.
- AI 컨텍스트: 값이 있는 영역 전체의 셀 값(서식 포함), 선택 범위, 활성 셀. (D9)
- 실제 LLM에 연결한다. API 키는 서버(Route Handler)에만 둔다.
- 제안이 없는 응답(질문에 대한 답 등)은 채팅 메시지로만 보여 준다. — P1

### A2. 범위를 지정한 요청 — P0

- 셀 범위를 선택한 상태에서 AI에게 요청하면 그 범위가 요청 대상으로 표시된다 (채팅 입력창에 "B2:D10" 칩).
- 범위를 지정한 요청에서 AI가 범위 밖 셀을 바꾸려 하면 그 제안은 버린다. 범위 없이 채팅으로 요청하면 시트 전체를 대상으로 한다. (D8)
- 선택 범위에서 바로 AI를 부르는 진입점(단축키 또는 우클릭/버튼). — P1

### A3. 검토 후 적용 / 버리기 — P0

- AI 결과는 시트를 바로 덮어쓰지 않는다. **생성은 AI 패널에서 따로 진행되고, 응답이 완료된 뒤 사용자가 "적용"을 눌러야 시트에 반영된다.** (D10)
- AI 패널에 제안이 **원래 값과 비교되는 형태**로 표시된다 (셀 주소 · 원래 값 · 제안 값).
- 시트에서는 제안 대상 범위만 강조해 어디가 바뀔지 알 수 있게 한다. 셀 값 자체는 적용 전까지 바뀌지 않는다.
- "적용" 버튼은 응답이 완료된 뒤에만 활성화된다. 전체 적용 / 전체 버리기를 할 수 있다.
- 셀 단위로 제외할 수 있다. — P1
- 적용 전까지 제안은 다른 참여자의 시트에 반영되지 않는다 (→ X2).

### A4. 스트리밍과 취소 — P0

- 결과가 만들어지는 과정이 실시간으로 보인다: 셀 제안이 생성되는 대로 AI 패널의 비교 목록에 하나씩 추가된다.
- 생성 도중 취소할 수 있다. 취소하면 서버의 LLM 호출도 중단된다.
- 취소하면 그때까지 생성된 부분 제안은 "취소됨"으로 패널에 남아 내용을 확인할 수 있지만 **적용할 수 없다.** 같은 요청으로 다시 생성할 수 있다. (D10)

### A5. 적용을 한 번에 되돌리기 — P0

- 적용한 AI 편집 전체가 실행 취소 1회로 되돌아간다.
- 적용 직전 입력과 합쳐지지 않는다.

### A6. 지연·실패 처리 — P0

- 요청 직후 즉시 "생성 중" 상태를 보여 준다. 첫 결과가 늦으면 경과를 알 수 있다.
- 실패 종류를 구분해 안내한다: 네트워크 오류, 시간 초과, 사용 한도/429, 서버 오류, 응답 형식 오류.
- 스트림이 중간에 끊기면 그때까지 받은 제안은 확인만 가능하고 적용할 수 없다(완료된 응답만 적용, D10). 같은 요청으로 재시도할 수 있다.
- 실패해도 시트와 채팅 입력 내용은 잃지 않는다.
- 응답 형식이 스키마와 다르면 그 항목만 버리고 나머지는 사용한다. — P1

### A7. 비용 안전장치 — P0

- 사용 한도를 설정할 수 있는 API 키를 쓴다. (과제 조건) → OpenRouter 선불 크레딧 소액 충전. 충전액을 넘으면 요청이 거절(402)되며, 이 경우도 A6의 "사용 한도" 실패로 안내한다. (D11)
- 요청당 최대 출력 토큰과 컨텍스트 크기를 제한한다. — P1

## X. 공동 편집과 AI가 만나는 지점

결정과 이유는 README에 기록한다. 아래는 제안안이다.

### X1. AI 생성 중 다른 참여자가 대상 셀을 수정·삭제하면 — P0

- 생성은 멈추지 않는다.
- 요청 시점에 대상 셀의 원래 값(base)을 저장한다.
- 적용할 때 셀마다 현재 값과 base를 비교하고, 달라진 셀은 **충돌**로 표시한다. 충돌 셀의 기본값은 "덮어쓰지 않음"이며, 원래 값 · 현재 값 · AI 값을 나란히 보여 주고 사용자가 고른다.
- 검토 중에 다른 참여자가 셀을 바꾸면 충돌 표시가 실시간으로 갱신된다.
- 이유: 사람이 직접 한 편집이 AI 결과에 조용히 덮이면 안 된다.

### X2. 한 사람이 AI 결과를 검토할 때 다른 참여자에게 보이는 것 — P0

- 대상 범위에 요청자 색의 점선 테두리와 "○○ · AI 생성 중 / 검토 중" 배지가 보인다.
- 제안 값은 보이지 않고, 셀 편집을 막지 않는다.
- 요청자가 적용하거나 버리거나 탭을 닫으면 표시가 사라진다.
- 이유: 제안은 확정되지 않은 개인 초안이다. 다른 사람 화면의 값이 바뀐 것처럼 보이면 혼란스럽고, 잠그면 요청자 탭이 죽었을 때 풀리지 않는 잠금이 생긴다.

### X3. 두 사람이 겹치는 범위에 동시에 AI를 요청하면 — P0

- 요청할 때 "○○님이 이 범위에서 AI 작업 중" 경고를 보여 주되 진행은 허용한다.
- 먼저 적용한 쪽이 반영되고, 나중에 적용하는 쪽은 X1의 충돌 검사에 걸린다.
- 이유: presence 기반 잠금은 두 탭이 동시에 요청하면 둘 다 성공할 수 있다. 적용 시점 검증 하나로 모든 경우를 일관되게 처리한다.

## Q. 코드 품질 — P0

평가 기준 2를 리뷰에서 확인할 수 있는 형태로 옮긴 것이다.

### Q1. 이해 가능성

- 모든 모듈은 한 문장으로 책임을 설명할 수 있다. 설명에 "그리고"가 두 번 이상 들어가면 나눈다.
- 비직관적인 결정(origin 구분, `stopCapturing`, IME 처리, 탭 종료 감지 등)에는 **이유**를 적은 짧은 주석을 단다. 무엇을 하는지만 적는 주석은 달지 않는다.
- 생성된 코드라도 커밋 전에 직접 읽고 설명할 수 없는 부분은 남기지 않는다.

### Q2. 중복과 복잡도

- 같은 규칙이 두 곳 이상에 있으면 하나로 모은다 (예: 셀 주소 계산, 범위 순회, 키 매핑).
- 두 번째 구현이 실제로 생기기 전에는 추상화(인터페이스, 제네릭 팩토리, 설정 객체)를 만들지 않는다. 예외: 네트워크 확장을 설명할 provider 경계.
- 사용하지 않는 코드, 주석 처리된 코드, 임시 로그를 남기지 않는다.
- 상태는 한 곳에만 둔다: 문서 데이터는 Y.Doc, 참여자 표시는 awareness, UI 전용 상태(선택, 편집 모드)는 React state.

### Q3. 구조와 가독성

- 폴더 구조와 의존 방향은 README "기술 선택 이유 > 폴더 구조와 의존 방향"을 따르고 ESLint로 강제한다.
- UI 컴포넌트는 Yjs를 직접 다루지 않고 `features/sheet`의 공개 API만 사용한다.
- 이름만 보고 역할을 알 수 있게 한다. 축약어(`c`, `r`, `tmp`)는 좁은 스코프의 반복 변수에만 쓴다.
- 한 파일이 약 200줄을 넘거나 한 컴포넌트가 여러 역할을 하면 나눌지 검토한다.

### Q4. 기술 선택 설명

- 라이브러리나 브라우저 API를 새로 도입하면 README "기술 선택 이유"에 이유와 검토한 대안을 적는다.
- 명세를 해석해 결정한 동작(아래 "결정 사항")은 README에 이유와 함께 적는다.

### Q5. 검증

- `lint`, `typecheck`, `test`가 통과한 상태로만 커밋한다.
- 순수 로직(`model/`, 충돌 판정, diff)은 단위 테스트로, 여러 탭 시나리오(C1~C7, X1~X3)는 E2E 테스트로 확인한다.
